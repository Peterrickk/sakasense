# SakaSense System Deployment Guide

This guide provides step-by-step instructions for deploying the SakaSense soil monitoring system for free using Render.com.

## Overview

The SakaSense system consists of:
- **Django backend (Next.js frontend)
- **Django API** with PostgreSQL database for data storage
- **ESP32 devices** that send soil sensor data

This guide will deploy both the frontend and backend to Render.com's free tiers, which include:
- Free web services (with automatic sleeping after inactivity)
- Free PostgreSQL database
- Free SSL certificates
- Automatic deployments from GitHub

## Prerequisites

1. GitHub account
2. Your SakaSense code in a local Git repository
3. Basic familiarity with command line/terminal

```yaml

  - type: web
    name: sakasense-backend
    env: python
    buildCommand: pip install -r requirements.txt

    envVars:
      - key: SECRET_KEY
        generateValue: true
      - key: DEBUG
        value: "False"
```

### E. Update API Routes for Proxy Pattern

Update `web/src/app/api/device/ingest/route.ts`:

```typescript
import { NextResponse } from "next/server";

/**
 * Proxy to Django backend for device ingestion.
 * Forwards the request to our own /api/device/ingest/ endpoint
 * which gets rewritten to the Django backend via next.config.js
 */
export async function POST(request: Request) {
  let body: unknown;
  try {
    body = await request.json();
  } catch {
    return NextResponse.json({ error: "Invalid JSON" }, { status: 400 });
  }

  const payload = body as {
    serial_number?: string;
    readings?: unknown[];
    recommendation?: unknown;
  };

  if (!payload.serial_number) {
    return NextResponse.json({ error: "serial_number required" }, { status: 400 });
  }

  try {
    // Forward to our own API endpoint (gets rewritten to Django)
    const response = await fetch(new URL('/api/device/ingest/', request.url), {
      method: 'POST',
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify(body),
    });

    const data = await response.json();
    return NextResponse.json(data, { status: response.status });
  } catch (error) {
    console.error("Error forwarding to Django:", error);
    return NextResponse.json(
      { error: "Failed to connect to backend" },
      { status: 502 }
    );
  }
}
```

Update `web/src/app/api/dashboard/route.ts`:

## Step 3: Deploy to Render.com

### A. Sign Up for Render
1. Go to [render.com](https://render.com)
2. Sign up using your GitHub account (recommended)
3. Verify your email address

### B. Create Backend Service
1. Click "New +" → "Web Service"
2. Connect your GitHub repository (`sakasense`)
3. Configure:
   - **Name**: `sakasense-backend`
   - **Region**: Choose closest to your location
   - **Branch**: `main`
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn mysite.wsgi:application`
   - **Environment**: Python 3
4. Under "Environment", add:
   - `SECRET_KEY`: (Click "Generate Value")
   - `DEBUG`: `False`
   - `ALLOWED_HOSTS`: `.onrender.com`
   - `CORS_ALLOWED_ORIGINS`: `https://sakasense-frontend.onrender.com,http://localhost:3000`
5. Click "Create Web Service"

### C. Create Database
1. In your backend service dashboard, click "Connect" → "Add a Resource"
2. Choose "PostgreSQL"
3. Configure:
   - **Name**: `sakasense-db`
   - **Plan**: Free
4. Click "Create Database" - Render will automatically set `DATABASE_URL`

### D. Create Frontend Service
1. Click "New +" → "Web Service"
2. Connect your GitHub repository (`sakasense`)
3. Configure:
   - **Name**: `sakasense-frontend`
   - **Region**: Same as backend
   - **Branch**: `main`
   - **Build Command**: `cd web && npm install && npm run build`
   - **Start Command**: `cd web && npm start`
   - **Environment**: Node
4. Under "Environment", add:
   - `NEXT_PUBLIC_API_URL`: `https://sakasense-backend.onrender.com/api`
5. Click "Create Web Service"

### E. Enable Automatic Deploys
For both services:
1. Go to "Settings" 
2. Under "Auto-Deploy", enable it
3. This ensures deployments happen automatically on every GitHub push

Should return: `{"service": "sakasense-api", "status": "ok"}`

#### Dashboard Endpoint
Visit: `https://sakasense-backend.onrender.com/api/dashboard/`
Should return JSON with your farm/plot data structure

#### Frontend
Visit: `https://sakasense-frontend.onrender.com`
Should show your SakaSense landing page

## Step 5: Set Up Your Data

### A. Create Admin User
1. In your backend service dashboard, click "Shell" → "New Shell"
2. Run: `python manage.py createsuperuser`
3. Follow prompts to create admin user (username, email, password)

### B. Access Django Admin
Visit: `https://sakasense-backend.onrender.com/admin/`
Login with your superuser credentials

### C. Set Up Your Farm
1. Add a User (if not created during createsuperuser)
2. Add a Farm:
   - Name: e.g., "My Farm"
   - Location: e.g., "My Location"
   - Farm Type: Select appropriate type
3. Add Plots:
   - Name: e.g., "Field 1"
   - Farm: Select your farm
   - Current Crop: e.g., "Tomato"
   - Area Label: e.g., "0.5 ha"
   - Status: Select appropriate status
4. Add Devices:
   - Serial Number: Your ESP32's unique identifier
   - Plot: Select the plot this device monitors
   - Owner: Select your user
   - Model: ESP32-SakaSense-v2 (or your actual model)
   - Battery Percent: 100 (or actual)
   - Status: Set to offline initially

## Step 6: Configure Your ESP32 Devices

Your ESP32 devices should now POST data to:
```
https://sakasense-backend.onrender.com/api/device/ingest/
```

### Example Data Format:
```json
{
  "serial_number": "KS-ESP32-004821",
  "battery_percent": 85,
  "readings": [
    {
      "timestamp": "2026-07-28T12:00:00Z",
      "pH": 6.5,
      "N": 70,
      "P": 40,
      "K": 75,
      "source": "live"
    }
  ],
  "recommendation": {
    "timestamp": "2026-07-28T12:00:00Z",
    "ranked_crops": [{"crop": "Tomato", "score": 85}],
    "guidebook_code": "5002",
    "fertilizer_prescription": {
      "product": "Tomato Bloom 10-20-10",
      "amount": "2 bags / ha",
      "timing": "Within 5 days",
      "notes": "Nitrogen and phosphorus levels are low for tomato"
    },
    "insight": "Nitrogen is trending low — apply tomato-specific fertilizer within 5 days per Guidebook code 5002.",
    "generated_on_device": true
  }
}
```

**Important Notes:**
1. The device must be assigned to a plot in Django admin for data to be stored
2. The serial number must exactly match what's in the device record
3. If the device isn't assigned to a plot, readings won't be saved (but you'll still get a 200 OK)

## Troubleshooting

### Common Issues & Solutions

**1. "Application Error" on Backend**
- Check logs in Render dashboard
- Most common: Missing SECRET_KEY or DATABASE_URL
- Solution: Verify environment variables are set correctly

**2. Frontend Can't Connect to Backend**
- Check browser console for CORS errors
- Verify `NEXT_PUBLIC_API_URL` is set correctly in frontend environment
- Ensure backend is actually running (check logs)
- Confirm API endpoints are accessible directly

**3. Device Data Not Appearing in Dashboard**
- Check if device is assigned to a plot in Django admin
- Verify serial number matches exactly
- Check backend logs for validation errors
- Remember: data only saves if device has a plot assigned

**4. Static Files Not Loading**
- Ensure `whitenoise` is properly installed and configured
- Check that `STATICFILES_STORAGE` is set correctly
- Verify `npm run build` completes successfully

**5. Database Connection Issues**
- Verify `DATABASE_URL` is set correctly
- Check that the PostgreSQL database was created successfully
- Look for connection timeout errors in logs

## Maintenance

### Updates
- Push changes to GitHub → automatic deployment on Render
- To manually trigger: Service dashboard → "Deploys" → "Trigger Deploy"

### Database Backups
- Render's free tier doesn't include automated backups
- Consider exporting data periodically via Django admin or shell
- For critical data, consider upgrading to a paid plan with backups

### Performance
- Free services sleep after 15 minutes of inactivity
- First request after sleep may take 10-30 seconds to "wake up"
- This is acceptable for most IoT dashboard use cases
- Consider upgrading if you need instant response times
